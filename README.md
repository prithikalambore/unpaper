# Unpaper: PDF to Word

A self-hosted web app that converts PDF files into editable `.docx` documents that open in
Microsoft Word (Windows and macOS), Apple Pages, Google Docs and LibreOffice Writer.

- **Frontend:** Next.js 16, TypeScript, Tailwind CSS 4 (`frontend/`)
- **Backend:** Python 3.12, FastAPI, PyMuPDF, python-docx, Tesseract OCR (`backend/`)
- **Conversion is deterministic and local.** No LLMs, no external AI or cloud services. Files never leave the server.

**Deploying it publicly?** See [DEPLOY.md](DEPLOY.md): one server, automatic HTTPS, rate limits,
and anonymous usage stats and feedback so you can see whether people find it useful.

## Quick start (Docker, local)

From the project folder, start it in the background:

```bash
docker compose up -d --build
```

Open <http://localhost:3000>. Stop it with:

```bash
docker compose down
```

| Task | Command |
| --- | --- |
| Start (no code changes since last time, faster) | `docker compose up -d` |
| Start after code changes (rebuilds the images) | `docker compose up -d --build` |
| Start in the foreground with live logs (Ctrl+C stops it) | `docker compose up --build` |
| Stop | `docker compose down` |
| Live logs of a background run | `docker compose logs -f` |

**If port 3000 is taken** ("Bind for 0.0.0.0:3000 failed: port is already allocated"), pick another
port. Put it in a `.env` file in the project folder once, and every command above uses it:

```bash
echo "FRONTEND_PORT=3002" >> .env
```

Then open <http://localhost:3002>. The `.env` file is git-ignored, so it stays on your machine.
For a one-off run, `FRONTEND_PORT=3002 docker compose up -d` works too. The Next.js log line
"Local: http://localhost:3000" refers to the port inside the container; use the port you chose.

### Usage stats and feedback

The local setup keeps anonymous usage counts and the "Did it work for you?" answers in a Docker
volume, so they survive restarts. With the app running:

```bash
docker compose exec backend python -m app.stats            # last 30 days
docker compose exec backend python -m app.stats --days 7
```

It shows visitors, uploads, conversions, failures, pages, the mode used, error types and every
feedback comment. No IP addresses, file names or document contents are stored. `docker compose
down` keeps the data; `docker compose down -v` deletes it.

Only the frontend is published. The browser talks to Next.js, which proxies `/api/*` to the backend
over the private Compose network. The backend container runs read-only, as a non-root user, with
uploads and results held in a RAM-backed `tmpfs`. Files never touch the host disk.

## Local development (without Docker)

Backend (Python 3.11+):

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
```

Frontend (Node 20.9+):

```bash
cd frontend
npm install
BACKEND_URL=http://127.0.0.1:8000 npm run dev
```

Then open <http://localhost:3000>.

OCR needs the Tesseract language data. On macOS, `brew install tesseract`. On Debian/Ubuntu,
`apt install tesseract-ocr tesseract-ocr-eng`. PyMuPDF finds it automatically, or you can set
`TESSDATA_PREFIX` to the `tessdata` folder. Without it, the app still runs: text PDFs convert
normally, and scanned PDFs return a clear "OCR is not available" error. `GET /api/health`
reports whether OCR is available.

## Tests

```bash
# Backend: 78 tests. The OCR test is skipped if Tesseract data isn't installed locally.
cd backend && .venv/bin/python -m pytest

# Same suite inside Docker, with Tesseract (nothing skipped)
docker build --target test -t pdf2word-backend-test backend && docker run --rm pdf2word-backend-test

# Frontend: type-check, lint and production build
cd frontend && npm run lint && npm run build
```

Test PDFs are generated by code, so no binary fixtures are needed. To write them to `samples/` for
manual testing:

```bash
cd backend && .venv/bin/python scripts/generate_samples.py
```

This produces `text.pdf` (headings, bold/italic, lists, link), `table.pdf`, `merged_table.pdf`,
`multipage.pdf` (running header and page-number footer), `two_column.pdf`, `image.pdf`,
`scanned.pdf` (image only, needs OCR), `blank.pdf`, `encrypted.pdf` and `malformed.pdf`.

**Checking compatibility with an independent editor:** `tools/libreoffice-check/check.sh <docx-dir> <out-dir>`
renders every `.docx` to PDF with LibreOffice in a network-isolated container. It fails for any
file LibreOffice can't open.

## Using it

1. Drop a PDF onto the page, or click **Choose a PDF**.
2. Choose a mode:
   - **Keep the original layout:** fonts, sizes, colours, alignment, indents, spacing, page size,
     margins and page breaks follow the PDF as closely as possible.
   - **Clean and easy to edit:** one consistent font (Calibri 11), standard spacing, no forced page
     breaks. Headings, lists, tables, images, links, bold and italic are kept.
3. Click **Convert to Word**. Progress shows the upload, then page-by-page processing.
4. Click **Download Word document**. Any warnings (for example, "OCR was used, please proofread")
   are shown with the result.

## Configuration

Backend environment variables:

| Variable | Default | Meaning |
| --- | --- | --- |
| `MAX_UPLOAD_MB` | `25` | Maximum upload size |
| `MAX_PAGES` | `300` | Maximum page count |
| `CONVERSION_TIMEOUT_SECONDS` | `300` | Worker process is killed after this |
| `MAX_CONCURRENT_JOBS` | `2` | Conversions running at once (each in its own process) |
| `MAX_QUEUED_JOBS` | `20` | Further uploads get `503 server_busy` |
| `JOB_TTL_SECONDS` | `600` | Results that are never downloaded are deleted after this |
| `WORKER_MEMORY_MB` | `4096` | Linux only: worker address-space cap (`RLIMIT_AS`). This is virtual memory; real RAM is capped by the container's `mem_limit` |
| `OCR_LANGUAGE` | `eng` | Tesseract language(s), for example `eng+deu` (install the matching data) |
| `OCR_DPI` | `300` | Render resolution for OCR |
| `WORK_DIR` | `$TMPDIR/pdf2word` | Per-job temp folders. Wiped on startup |
| `ALLOWED_ORIGINS` | `http://localhost:3000,...` | CORS, only needed if a browser calls the backend directly |
| `RATE_LIMIT_PER_HOUR` / `RATE_LIMIT_PER_DAY` | `20` / `60` | Conversions per visitor (IP; IPv6 grouped per /64). `0` disables |
| `MAX_ACTIVE_JOBS_PER_CLIENT` | `1` | Conversions one visitor can have running or queued |
| `FEEDBACK_PER_HOUR` | `10` | Feedback submissions per visitor |
| `TRUST_CLIENT_IP_HEADER` | off | Use the `X-Client-IP` header set by the frontend proxy. Enable only when the backend is reachable solely through the frontend (as in the production compose file) |
| `STATS_DB` | empty (off) | SQLite path for anonymous usage counters and feedback. View them with `python -m app.stats` |

Frontend: `BACKEND_URL` (server-side, read at runtime; default `http://localhost:8000`).

## API

All errors have the shape `{"error": {"code": "...", "message": "..."}}`.

| Method & path | Purpose |
| --- | --- |
| `GET /api/health` | `{status, ocr_available, limits}`. `?visit=1` (sent by the UI) counts an anonymous daily unique visitor |
| `POST /api/feedback` | JSON `{useful: bool, comment?: str (≤1000), mode?, pages?}` → 204 |
| `POST /api/convert` | multipart `file` (PDF) + `mode` (`layout` or `clean`) → `202 {id, status}` |
| `GET /api/jobs/{id}` | `status` (queued/processing/done/failed), `stage`, `progress` 0–100, `current_page`, `total_pages`, plus `result` or `error` |
| `GET /api/jobs/{id}/download` | The `.docx`. The server deletes its copy once it has been sent |
| `DELETE /api/jobs/{id}` | Cancel a job and delete its files |

Error codes: `invalid_file_type` (415), `file_too_large` (413), `empty_file`, `missing_file`,
`invalid_mode` (400), `length_required` (411), `rate_limited` and `too_many_active` (429, with
`Retry-After`), `server_busy` (503), `job_not_found` (404),
`not_ready` (409). A failed job reports one of: `malformed_pdf`, `encrypted_pdf`,
`too_many_pages`, `no_content`, `ocr_unavailable`, `ocr_failed`, `conversion_timeout`,
`invalid_output`, `resource_limit`, `conversion_failed`.

## Architecture and key decisions

```
browser ──► Next.js (UI + /api proxy) ──► FastAPI ──► worker process per job
                                              │          PyMuPDF extract → layout analysis
                                              │          → python-docx write → validate
                                              └── in-memory job table, janitor thread
```

**Job model, not one long request.** An upload returns a job id immediately. The UI polls for
real per-page progress. This also keeps long OCR runs from hitting proxy timeouts.

**One process per conversion.** Malformed PDFs can crash or hang PDF engines. A separate process can
be killed on timeout, memory-capped on Linux, and can't take the API down. It is started with
`spawn`, never `fork`, because the server is multithreaded.

**An intermediate model between PDF and Word** (`app/converter/model.py`). The stages are
extraction (`extract.py`, `tables.py`, `ocr.py`), layout analysis (`layout.py`), DOCX writing
(`docx_writer.py`) and validation (`verify.py`). Each stage is pure and tested on its own.

**Flowing text, not positioned boxes.** Many converters place every line in an absolutely
positioned text frame. That looks identical but is miserable to edit and renders badly in Pages.
This converter rebuilds paragraphs, headings (Word's built-in Heading 1–6 styles), bullet lists
(List Bullet styles), real tables and inline images. "Keep the original layout" mode then
reproduces the look through fonts, sizes, spacing, indents, page size, margins and page breaks.

**Layout heuristics** (all geometric and typographic, deterministic):
- *Body size* is the most common font size by character count. *Headings* are short paragraphs
  noticeably larger than the body, or single bold lines. Heading levels follow the document's
  size hierarchy.
- *Paragraphs* are rebuilt from lines using line pitch, vertical gaps, indentation, font changes
  and sentence endings. Hyphenated line breaks are re-joined, as are sentences that the PDF split
  across a page boundary.
- *Reading order* detects two-column regions: wide text on both sides of the centre, read left
  column first.
- *Running headers and footers* are text repeated near the top or bottom of at least half the
  pages. They move into Word's header and footer, and page numbers become live `PAGE` fields.
- *Tables* come from PyMuPDF's ruling-line detection. Cell text keeps bold, italic and size, and
  merged cells are rebuilt from cell geometry. PyMuPDF 2's ML-gated table mode is disabled because
  it mis-read merged cells in testing and is slower.
- *Ligatures* (ﬁ, ﬂ) are expanded so text stays searchable and spell-checkable.

**Output validation.** Every document is re-opened and checked (ZIP integrity, required parts,
python-docx parse, non-empty content) before it can be downloaded. A conversion that would produce
an empty or corrupt file fails with an error instead.

**Privacy.** Uploads are streamed to a per-job `0700` directory. The PDF is deleted as soon as the
worker finishes, including on failure or timeout. The job directory is deleted after download, on
cancel, on failure, or after `JOB_TTL_SECONDS`. `WORK_DIR` is wiped on startup. Logs contain only
job ids, sizes, page counts, timings and error codes: never file names or document text.
Exceptions are logged by type only, because messages can contain document text. MuPDF diagnostics
are silenced. Template metadata ("python-docx" as author) is stripped from the output. Responses
are `Cache-Control: no-store`.

**Input safety.** The extension and content type are checked, then `%PDF-` magic bytes, then a
streamed size limit (`Content-Length` is checked before the body is parsed). Encrypted, malformed
and over-long PDFs are rejected with specific errors. The user's filename is never used on disk.
It is only sanitised into the download name, with an RFC 5987 `filename*`. Link targets are
limited to `http`, `https` and `mailto`. The Next.js proxy only forwards allow-listed path
segments and headers.

## Verification performed

- 78 backend tests pass in Docker with Tesseract, covering rate limits, spoofed client IPs,
  stats that contain no personal data, feedback validation, and text extraction, headings, bold and
  italic, fonts, lists, hyperlinks, two-column order, headers and footers with page fields, page
  breaks, tables and merged cells, images, OCR (with OCR, without OCR, and mixed documents),
  blank, encrypted, malformed, non-PDF, oversized and empty files, the page limit, timeouts,
  cancellation, TTL purge, temp-file cleanup and DOCX validity for every sample in both modes.
- Real-world PDFs converted: a 163-page licence agreement (about 11 s) and a 228-page
  acknowledgements document (about 14 s).
- Outputs opened and rendered in **LibreOffice Writer** (all 14 sample outputs plus the 163-page
  document) and **macOS Quick Look** (Apple's built-in Office renderer).
- End-to-end UI tested in a browser at desktop and mobile widths, in light and dark mode: upload,
  progress, download (a valid `.docx`), validation errors, malformed and scanned-without-OCR errors.
- **Not verified directly:** Microsoft Word, Google Docs and the Apple Pages app itself. Pages
  automation was blocked by macOS permissions in the environment where this was built. The output
  uses only standard WordprocessingML features (built-in styles, inline images, simple tables,
  complex fields), but open a few converted files in those apps before relying on them.

## Known limitations

Formatting preservation is best-effort. It is not pixel-perfect and has not been verified against
every kind of PDF.

- **Complex layouts.** Magazine layouts, text wrapped around images, sidebars, text boxes and
  three or more columns are flattened into one reading order. Two-column pages become a single
  column. Floating objects become inline.
- **Equations** come through as plain text or symbols (often with broken ordering), not editable
  Word equations.
- **Vector graphics** (charts and diagrams drawn as paths) are not converted. Only embedded raster
  images are. Rotated or vertical text is left out (with a warning).
- **Fonts.** PDF fonts are mapped to family names (Helvetica → Arial, Times → Times New Roman, and
  so on). Embedded or unusual fonts the reader doesn't have are substituted, which changes line
  breaks and page count. Symbol fonts (Wingdings bullets) are mapped where known.
- **Tables** are detected only when they have ruling lines. Borderless tables come through as
  text, with tabs separating cells on the same line. Cell shading and per-cell borders are not
  copied, and tables inside scanned pages are not detected.
- **Lists.** Bullets become real Word bullet lists. Numbered items keep their literal numbers
  ("1.", "a)") instead of Word auto-numbering, so inserting an item doesn't renumber the rest.
- **Headings** are inferred from size and weight. Documents that signal structure by other means
  (colour only, small caps) may not get heading styles.
- **OCR** quality depends on scan quality. Only languages whose Tesseract data is installed work
  (English by default). Recognised text gets approximate sizes but no font identity. Handwriting
  is not supported.
- **Right-to-left and vertical scripts** are not specifically handled.
- **Forms, annotations, comments, bookmarks, footnote linking and tables of contents** are not
  converted as interactive structures. Their visible text is kept.
- **Scaling.** Job state is held in memory, so run one API process per container (as configured).
  To scale out, run more containers behind sticky routing, or move the job table to Redis.
- There is no login by design. Abuse is limited per IP address: people sharing one IP (an office
  or campus network) share one allowance, and someone with many IPs can exceed it. There's no
  CAPTCHA.
